# Register der Schutzmaßnahmen (`security-guards`)

Stand: 2026-10-11, abgeleitet aus Code und `docs/decisions/phase-3-plan.md` (Abschnitte 2, 3, 5, 11, 12.14.8).
Zweck: Jede Schutzmaßnahme hat mindestens einen Test, der rot wird, wenn sie fehlt. Der Agent `mutation-prober`
(Plan, Abschnitt 13) prüft das, indem er die Mutation in einem isolierten Worktree anwendet und nur die genannten
Tests laufen lässt. Bleiben sie grün, ist die Maßnahme „zahnlos“.

**Lesen:** `Modul` nennt die Stelle (Funktion statt Zeilennummer, weil Zeilen wandern). `Tests` sind die Tests, die
anschlagen **müssen**. `Mutation` ist eine einzeilige Anweisung; sie ist **genau so** anzuwenden und danach zu
verwerfen. `Status`: `umgesetzt` (Code und Tests vorhanden), `teilweise` (Werkzeugschicht ja, Schleife/Trace erst in
Phase B), `geplant` (nur im Plan, noch kein Code — nicht mutierbar).

**Regeln für die Pflege:** Neue oder geänderte Schutzmaßnahme → Zeile hier im selben Commit; eine Maßnahme ohne
Test, der bei ihrer Mutation rot wird, ist ein Befund, kein Eintrag mit „keine“. Die `SM-xx`-IDs des Plans (12.14.8)
stehen in der Spalte „Plan“.

Testpfade sind relativ zu `tests/unit/`.

4. **SG-03b:** Ob `test_tools_schemas.py::test_tool_definitions_are_deterministic_strict_and_exclude_host_only_tools`
   die Abwesenheit von `confirm_peer_set` in der Tool-Liste tatsächlich erzwingt, ist nicht mutationsgeprüft; die
   Mutation „`confirm_peer_set` in `TOOLS` eintragen“ ist nicht als Einzeiler formuliert.

Mutationen SG-01 bis SG-11a (außer SG-03b-Tool-Liste) wurden beim Anlegen einmal von Hand im Wegwerf-Worktree
angewendet: Alle Testgruppen wurden rot, jeweils bei grüner Ausgangslage.

## Hinweise zur Mutation

- Mutationen gelten nur im isolierten Worktree des `mutation-prober`; sie werden nie im Haupt-Arbeitsverzeichnis
  angewendet und nie committet.
- Je Mutation nur die genannten Tests laufen lassen (`-k` oder Node-IDs), vorher denselben Aufruf ohne Mutation
  (muss grün sein), danach die Mutation zurücknehmen (`git checkout -- <Datei>` im Worktree).
- Ergebnis je Zeile: `angeschlagen` (mindestens ein Test rot), `zahnlos` (alle grün), `nicht anwendbar` (Fragment
  nicht gefunden — Register ist veraltet).
